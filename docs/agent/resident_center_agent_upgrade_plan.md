# 주민센터 Agent 현황 및 Phase 6 개선 계획

## 기준 브랜치의 구현

| 항목 | 현재 구현과 한계 |
|---|---|
| 자료 검색·출처 | `backend/app/services/resident_center_agent.py`가 `backend/app/data/resident_center_services.json`의 수동 요약 10건을 키워드 점수로 검색해 최대 3건을 선택한다. 구로구·도봉구·행정안전부 등의 공개자료이며 URL·자료 ID·지역을 함께 제공한다. |
| 자료 최신성 | 자료에 2026-11-02 확인일, 지역·한계를 기록했다. 시행일은 미확인이다. JSON을 캐시하므로 수정 확인에는 서버 재시작이 필요하다. 자동 갱신·만료 판정은 미구현이다. |
| 업무 유형 추정 | 현재 문장의 키워드가 우선이다. 명시적 업무가 없는 일부 후속 질문은 최근 사용자 발화에서 업무를 찾는다. 별도 업무 분류 모델과 일반 문맥 판별은 미구현이다. |
| 도구 선택 | 서버의 로컬 JSON 검색이 고정 경로다. 업무별 도구 선택과 자율 도구 호출은 미구현이다. |
| 근거 기반 답변 | 검색 요약과 근거 ID 지침을 Provider에 전달하고 서버가 검색 출처를 덧붙인다. 근거별 주장 일치나 최신 요건의 자동 사실검증은 미구현이다. 기본 Mock Provider는 기존 합성 응답을 생성한다. |
| 보호 프록시 및 Validator | `/proxy/chat`, `/proxy/chat/stream`에서 입력 탐지·정책·송신 직전 가드 후 처리된 질문과 이력을 검색에 쓴다. 답변과 출처 생성 후 반환 직전 Validator가 검증한다. SSE는 버퍼링 후 검증한다. `/proxy/analyze`는 검색·생성 없이 사전 검사한다. |

기존 Agent 설명, 구현 및 회귀 근거는 [Agent 문서](../resident_center_agent.md), [검색 서비스](../../backend/app/services/resident_center_agent.py), [대화 검증](../../backend/tests/test_resident_center_conversation.py)에 있다. Phase 1은 코드와 공식 행정자료의 저장 상태를 확인했다. 자료 링크의 현재 요건과 실제 OpenAI 생성 품질은 이번 점검에서 측정하지 않았다.

## Phase 6 개선 범위

| 기능 | 설계와 평가 |
|---|---|
| 일반 민원 안내 | 지역·업무 구분을 명확히 하고 관련 자료를 검색한다. 복수 지역·유사 업무를 혼동하는 사례를 검증한다. |
| 복지제도·신청 절차 | 공식 제도 및 신청자료를 지역·적용일과 함께 제공한다. 정보 부족 시 담당 기관 확인으로 안내하고 개인별 자격을 결정하지 않는다. |
| 행정서류 발급 안내 | 발급처, 준비서류, 수수료, 본인·대리인 조건을 자료 근거에 연결한다. 발급 행동 없이 안내 정확성을 검증한다. |
| 민원 답변 초안 | 필요한 사실만 포함한 초안을 표기하고 담당자가 검토한다. 개인정보 유도, 검증되지 않은 행정요건, 자동 접수 여부를 점검한다. |
| 공식 자료 검색과 출처 | 허용된 공식 출처를 버전으로 관리한다. 문서별 지역·확인일·시행일·만료 검토일과 근거 구간을 저장하고, 상충·누락 시 근거 부족을 표시한다. |

업무 분류와 검색을 먼저 개선하고 업무별 읽기 전용 검색의 적합성을 확인한다. 답변 주장별 자료 ID·근거 구간 일치율, 자료 상충 시 응답, 후속 업무 선택의 정확성, 검증된 정상 차단과 안전한 실패를 함께 측정한다. 검색 문서와 사용자 이력은 비신뢰 데이터이며, Validator의 출력 검증과 별도로 근거 일치 검사가 필요하다.

행정망 접근·주민정보 조회·최종 복지 자격 판단·자동 접수는 범위 밖이다. 공식 업무자료는 Agent의 RAG에만 두고 보안 탐지 모델의 학습 코퍼스와 분리한다.
