## 설계와 보존 사항

- 현재 API·인증·Provider 선택·대화 이력 제한·기존 키워드 검색·입력 정책·마스킹·출력 Validator를 유지했다.
- 인감 등록과 증명서 발급, 장애인 등록과 증명서 발급, 수급자 증명과 지원 신청은 별도 자료로 구분했다.
- 특정 센터의 운영시간·전화·담당 창구는 미등록이다. 지역 참고자료를 다른 지자체의 확정 기준으로 사용하지 않는다.
- 의료기록·소득·계좌 등 기관에 제출하는 서류의 내용을 채팅으로 요구하지 않는다.
- 기존 평가 질문의 action·라벨은 바꾸지 않았다. 신규 100건은 검색·후속·미수록·보안 회귀용이며 모델 품질 벤치마크로 사용하지 않는다.
- 탐지 규칙과 benchmark 성능 수치, 실제 ML-DSA가 아닌 Mock signer 기반 감사 로그 무결성 구조는 유지했다.

## 발견·수정한 제한

최초 추가 검사에서 일부 한국어 공격 문장이 탐지 결과의 `matched_terms`를 통해 로그에 남아 원문 비저장 검사 1건이 실패했다.
로그 직전 재귀 정리에서 `matched_terms`·`matched_text`를 제거하고 분류·reason code·건수는 유지했다.
기존 로그 자동 정리나 전체 로그 스키마 allowlist 전환은 하지 않았다.

## 완료 조건과 후속 작업

자료 JSON 파싱, 출처·범위 계약, 신규 100개 시나리오, 기존 관련 서버·감사 서명 회귀, 화면 계약 검사를 실행했다.
정확한 통과 수·명령과 한계는 검증 보고서를 따른다. 검토 브랜치의 PR #15를 갱신하고 기본 브랜치에는 자동 병합하지 않는다.

후속으로 승인된 모델에서 이 질문들을 실제 실행해 근거 불일치·환각·미확인 답변의 과도한 확정을 사람이 평가한다.
대상 센터가 정해지면 센터별 공식 운영정보를 별도 대조한다. 검색 실패 표현은 이번 목록에 없는 독립 질문으로 확인한다.
