# Security Limitations

## 목적

이 문서는 현재 MVP의 보안 한계와 운영 시 주의사항을 발표/제출용으로 명확히 기록하기 위한 문서다.

## 현재 범위

- 이 프로젝트는 입력/출력 텍스트 기반의 PII 탐지와 prompt injection 완화를 목표로 한다.
- 네트워크 DLP, 사용자 인증 통합, 권한 기반 데이터 접근 제어, 데이터베이스 레벨 마스킹까지 모두 해결하는 제품은 아니다.
- 따라서 "LLM 보안 전체"가 아니라 "프록시 레이어에서의 1차 차단과 감사"에 초점을 둔 MVP로 설명해야 한다.

## 탐지 한계

- 정규식 기반 PII 탐지는 형식이 명확한 데이터에는 강하지만, 비정형 개인정보와 문맥형 민감정보에는 한계가 있다.
- 룰 기반 injection 탐지는 명시적 우회 표현에는 강하지만, 새로운 jailbreak 문구나 복합 role-play 우회에는 오탐/미탐이 남을 수 있다.
- 선택형 경량 분류기 artifact가 없는 환경에서는 `regex/rule + fallback heuristic` 중심으로 동작하므로, 문맥형 일반화 성능을 충분히 주장할 수 없다.
- 다국어 혼합 입력, 인코딩 난독화, zero-width 문자 삽입, 이미지 속 텍스트 기반 PII는 현재 범위 밖이다.

## 운영 한계

- 현재 감사 로그는 메타데이터 중심이며, 원문 prompt/response를 저장하지 않는다. 이는 개인정보 보호에는 유리하지만 사후 포렌식 정보는 제한될 수 있다.
- mock upstream 기반 시연은 재현성이 높지만, 실제 외부 LLM 연동 시 지연 시간, 응답 분산, 네트워크 오류가 추가될 수 있다.
- 관리자 API는 토큰 기반 보호를 사용하지만, 조직 SSO/사내 IAM 연동까지 포함하는 수준은 아니다.

## 평가 해석 한계

- 내부 회귀셋 F1 1.000은 현재 규칙이 기존 케이스를 안정적으로 처리한다는 뜻이지, 실제 운영 일반화 성능을 보장하는 수치는 아니다.
- 외부 스타일 검증에서 Injection precision이 낮아지는 것은 경계 문장과 설명형 문장을 아직 완전히 분리하지 못한다는 신호다.
- baseline 비교표에서 `Lightweight Model Only = N/A`는 현재 실행 환경 문제를 뜻할 수 있으며, 모델 자체 성능이 0이라는 의미는 아니다.

## 발표 시 안전한 표현

- "모든 개인정보 유출을 막는다" 대신 "프록시 레이어에서 주요 PII와 명시적 정책 우회 요청을 우선 차단한다"라고 설명한다.
- "모델이 모든 우회 공격을 이해한다" 대신 "정규식, 룰, 선택형 분류기 경로를 병합해 탐지 범위를 넓혔다"라고 설명한다.
- "운영 배포 완료" 대신 "공공기관·사내망 환경을 가정한 MVP와 시연 가능한 프로토타입"이라고 설명한다.

## 후속 개선 과제

- 선택형 경량 분류기 artifact와 학습 파이프라인을 재현 가능한 형태로 포함
- 외부 스타일 검증 데이터셋 확대 및 FP/FN 분석 자동화
- 이미지/OCR 기반 PII 탐지, 문서 파일 업로드 검사, 역할 기반 정책 차등화
- 조직 인증 체계와 관리자 API 권한 정책 강화
